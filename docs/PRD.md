# Product Requirements Document (PRD)

**Project:** EcoConsensus: stance detection on global warming for Hindi and Bengali comments
**Course:** CSET 346 Natural Language Processing (project assignment, `papers/for_college/PS.pdf`)
**Version:** 2 (replaces the first draft)
**Timeline:** 5 days
**Status:** Draft for sign-off

If a feature is not on this list, it is not in the build.

---

## 1. What this project is

Given the fixed claim **"Climate change and global warming is a serious concern."** and a YouTube comment, decide the comment's stance:

| Label | Meaning (from the assignment) |
|---|---|
| `favour` | The comment agrees that climate change or global warming is a serious concern |
| `against` | The comment disagrees with that claim |
| `neutral` | Neutral, unrelated, or no clear stance |

Label ids (final, used everywhere): **0 = favour, 1 = neutral, 2 = against**.

Comments are in **Hindi and Bengali** (pure script, mixed with English, or romanised). English is used for training and experiments. The final system is a **stacked ensemble** of two fine-tuned transformers (MuRIL, IndicBERT v2) and two LLMs reached through APIs, compared against two baselines. Scoring is **Macro-F1** (primary), plus accuracy, precision, recall and confusion matrix.

There is no UI. The project is used through two scripts: `test.py` (evaluators) and `inference.py` (single comments).

## 4. Goals and non-goals

**Goals**
1. Classify stance (favour / neutral / against) for Hindi and Bengali comments against the fixed claim.
2. Beat the TF-IDF baseline on Macro-F1 and show how the ensemble compares with the best single transformer and best single LLM.
3. Make every experiment traceable and every report reproducible by script.
4. Accept an evaluator file with unknown columns and values, reconfigurable in seconds.
5. Cover the assignment's deliverables and as many bonus items as time allows.

**Non-goals**
- No UI, no serving, no deployment.
- No other claims (one fixed claim only).
- No heavy hyperparameter search.
- No full fine-tuning of all layers.

## 5. Data

| Dataset | Role | Size | Quality |
|---|---|---|---|
| **Pol-NLI** (political NLI, climate-change premises against the hypothesis "Climate change is a serious concern."), processed and translated | Training | about 3,517 train and 90 validation sentences, a subset is enough | Lower: NLI sentences, not comments |
| **SemEval-2016 Task 6** (tweets, target "Climate Change is a Real Concern"), processed and translated | Method experiment (small subset), stacking training, own testing | 564 tweets | Higher |
| **Evaluator test file** | Final test | Unknown | Unknown format, unknown columns |

- Each sentence exists in English, Hindi (pure, code-mix, romanised) and Bengali (pure, code-mix, romanised), so one source sentence gives up to 7 rows.
- **Only Hindi and Bengali are used.** The Bagheli translations made by mistake are ignored; Bengali translations are in `data/raw/translated/Bengali/` (`pure_bengali`, `bengali_code_mix`, `banglish`).
- Label mapping for Pol-NLI `entailment`: 0 = favour, 1 = neutral, 2 = against. For SemEval: FAVOR = favour (0), NONE = neutral (1), AGAINST = against (2).
- The `augmented_hypothesis` and `review` columns are dropped from processed data (the augmented claim may be used later as an optional augmentation).
- The claim is the fixed English claim for every row (a switch allows each file's own claim instead).
- The 171K-row Pol-NLI dataset is not used beyond the provided processed subset.

## 6. Features

### F1. Preprocessing
- **Done when:** emojis kept; `@handle` becomes `@USER`; URLs become `URL`; `RT` prefix and the `#SemST` tag removed; hashtag symbol dropped, word kept; Unicode NFC; whitespace collapsed; empty text does not crash. One function is used in the experiment, `src/`, `test.py` and `inference.py`.
- Counts toward the bonus "novel preprocessing" only if you add and evaluate something beyond this (optional).

### F2. Splitting
- **Done when:** SemEval is split into `dev` (70%) and `test` (30%), stratified by label and grouped by source tweet, so no translation of a test tweet is in dev. The split is saved with its seed and reused everywhere. Pol-NLI is sampled as a stratified subset by sentence. Class ratios are reported per split.
- The experiment notebook makes its own split of its small SemEval subset (train / val / test by tweet, stratified); it is used only to choose methods.

### F3. Baselines
- **Done when:** Majority class and TF-IDF (character + word n-grams) with Logistic Regression are trained on the same data and scored with the same metrics as every other model.

### F4. Experiment notebook (`experiment/experiment.ipynb`)
- **For:** Builder. One self-contained notebook for Colab (Kaggle as backup).
- **Data:** only a small SemEval-2016 Task 6 subset in English, Hindi (3 variants) and Bengali (3 variants), built on the Mac by `experiment/prepare_data.py` as `experiment_data.zip` and uploaded to Google Drive. The notebook unzips it.
- **Done when:**
  - It compares four methods for both MuRIL and IndicBERT v2: head only, head plus last N layers, LoRA, QLoRA.
  - Runs execute one after another and resume after a disconnect (finished runs are skipped).
  - Results go to MLflow (`mlflow.db` + `mlartifacts/`) and to a code-generated Markdown report, all in `MyDrive/EcoConsensus/experiment_outputs/`.
  - The report recommends one method per model by a stated rule, with per-language and per-variant scores.
- `experiment/SETUP.md` explains data upload and running on both platforms.

### F5. Fine-tuning for the final models (`src/training/`)
- **Done when:** the chosen method is trained for each model with class-weighted loss, AdamW, dropout, early stopping and per-epoch checkpoints, on Colab or Kaggle, with resume. Weights are saved under `models/finetuned/`.
- **One model at a time.** Colab gives about 14.7 to 15.8 GB of VRAM, so the two transformers are **not** trained together. Each is trained in its own run (own command, own checkpoint folder); the second starts only after the first has saved its best checkpoint.

### F6. LLM classifier (provider-agnostic, batched, cached)
- **Done when:**
  - Two providers are configured in `.env` and a config file; nothing is hard-coded.
  - A fixed system prompt (`prompts/stance_system_prompt.md`) takes a **batch** of comments and returns one JSON label per comment. `inference.py` sends a batch of one.
  - Every result is cached per entry (provider, model, prompt version, claim, comment). Reruns never repeat a call that is cached.
  - Daily-limit errors stop the run cleanly; the next run continues from the cache.
  - Unparseable answers are counted, retried once individually, then marked unavailable.

### F7. Stacking ensemble
- **Done when:** the design in `docs/STACKING.md` is built as three separate steps: (1) each transformer trained alone, (2) `src/training/train_inference.py` runs both fine-tuned transformers and both LLMs over SemEval `dev` and `test` and saves the **features** (one file per component, resumable), (3) `src/training/train_meta.py` trains the meta-model from those feature files. Fallback variants cover missing components. SemEval `test` is touched only for final numbers.

### F8. `test.py` (evaluator entry point)
- **For:** Evaluator or you, on the spot.
- **Done when:**
  - It reads the dataset in `test/` (first supported file, or `--file`).
  - A **CONFIG block at the top of `test.py`** maps the evaluator's column names and label values, with the fixed claim as fallback. Changing about five lines configures it. The same settings are available as flags (see `docs/INFERENCE.md`).
  - It runs the baselines, the best single transformer, the best single LLM and the ensemble, and writes:
    - `test/result_<timestamp>.txt` and `.md`: full report (all metrics, per-class results, confusion matrices, per-language results when a language can be detected, runtime, fallbacks used, warnings)
    - `test/predictions_<timestamp>.csv`: `ID,Predicted Label` as the assignment requires
    - logs in `outputs/logs/`, metrics in `outputs/metrics/`, predictions in `outputs/predictions/`
  - If the file has no labels, it writes predictions and a short report without metrics.
  - It never overwrites an earlier result.
  - It saves a list of misclassified examples for error analysis when labels exist.

### F9. `inference.py`
- **Done when:** one comment (or a small file) in, one label out, with per-model votes. Documented in `docs/INFERENCE.md` for macOS, Linux and Windows with every flag explained.

### F10. Reports
- **Done when:** every report is Markdown (`test.py` also writes the `.txt` version you asked for), produced only by script code, with a timestamped name, written in create-only mode so an existing report is never replaced.

### F11. Experiment tracking
- **Done when:** MLflow records every experiment run and the final comparison. The store is a SQLite file that can be copied back from the cloud.

### F12. Checkpointing and resume
- **Done when:** training saves a checkpoint each epoch to persistent storage; a restarted job continues from it; the best checkpoint is kept separately.

### F13. Secrets
- **Done when:** API keys live only in `.env` (git-ignored). `.env.example` lists every variable with no values.

### F14. Documentation and citations
- **Done when:** README, `docs/` and `experiment/SETUP.md` exist; code is commented where needed, not everywhere; every library, model, dataset and LLM used is cited with its authors or owners (see README "References"), including the LLMs used for translation and classification, as the assignment requires.

## 7. Success criteria

| Criterion | Target |
|---|---|
| Comparison | One table: Majority, TF-IDF, best transformer, best LLM, ensemble, all with Macro-F1, accuracy, precision, recall |
| Honesty | If the ensemble does not beat the best single model, the report says so and gives a likely reason |

## 8. Constraints

- **Hardware:** MacBook Pro M3, 8 GB RAM for code, tests, baselines, `inference.py`, `test.py`. Training on Colab or Kaggle GPUs.
- **Cost:** free API tiers only. Gemini and OpenRouter are excluded. Request limits drive batching and caching.
- **Time:** 5 days.
- **Frameworks:** PyTorch and Hugging Face; scikit-learn only for baselines, metrics and the meta-model.
- **Python:** 3.13 or newer locally; cloud platforms use whatever Python they provide (the code stays compatible with 3.11 and later).

## 9. Risks

| Risk | Mitigation |
|---|---|
| Domain shift: training sentences are not YouTube comments | Train on code-mix and romanised variants, score on SemEval tweets, report the gap |
| Few `against` examples in SemEval (class imbalance) | Class weights, per-class reporting, bootstrap intervals, grouped stratified split |
| Machine-translated Hindi and Bengali | State the limit in the report; spot-check translations for label preservation |
| Unknown evaluator format | CONFIG block, alias matching, clear error messages listing the columns found |
| Free LLM limits | Batching, cache, resume, fallback ensembles |
| Colab or Kaggle disconnects | Checkpoints and resumable jobs |
| Experiment subset is small (few `against` tweets) | Every `against` tweet kept in the subset, per-class F1 and parsimony rule in the report |
| Five days | Cut-lines in `IMPLEMENTATION_PLAN.md` |
